# 食刻桌面卡片实施记录

日期：2026-10-03。用户已确认设计方案；代码实施与源码静态审查完成。构建、部署和运行验证未执行，由用户负责。

## 已落实的行为

- 2×2 使用 A 版信息布局：小品牌标识、推荐名称、分类/地点、短评分、独立价格与查看详情提示。顶部刷新按钮的视觉图标为 17vp，触摸区域为 44×44vp，与正文点击区域分离。
- 2×4 左文右图，右侧封面占内容宽度的 36%，采用等比裁剪；正文和图片分别点击均进入同一条详情。
- `ServiceCard` 名称、默认 2×2、FormExtensionAbility 名称与已有路由保持兼容；配置新增 `2*4`，支持宿主允许的尺寸调整。远端发送方固定使用 `formName: ServiceCard`，因此最终采用一个名称下的两个尺寸，避免新增 formName 后远端无法匹配。
- 从 Want 的尺寸枚举取得 2×2 / 2×4，单独存储每个 formId 的尺寸，更新和 onSizeChanged 均延续该尺寸。创建预览没有 formId 时也直接使用本次 Want 的尺寸。
- 使用宿主尺寸回调设置内容高度策略。名称在较矮卡片中使用一行，高度达到 176vp 时允许两行；低于 156vp 时隐藏辅助地点行并缩小内边距。最大字号使用 fp，适配下限使用 vp，避免系统放大后连最小字号也超出固定信息行。
- 有效评分显示 `4/10` 等短值；异常或缺失显示“未评分”。缺失价格显示“价格待补充”。无推荐时仅显示发现入口，不显示伪造分数或价格。
- 刷新兼容直接字符串和 postCardAction 序列化的 JSON 参数。刷新只重新绑定已有本地摘要与封面，不下载新的推荐。
- 新增卡片专用链接色，浅色使用 #C8462C，深色使用 #FF7B58；图标提供对应深浅色版本。正文操作与封面使用原生 Button，提供操作名称和完整推荐信息的读屏描述。

## 封面与同步

1. 应用前台更新推荐，先同步文字和图片身份，再复用现有公开已审核媒体接口取得缓存图片。
2. 使用 Image Kit 生成最长边不超过 480px、质量 80 的 JPEG，文件大小上限 512 KiB，保存于应用 filesDir 的独立卡片缓存目录。该缓存不会随普通媒体缓存清理一同丢失。
3. 仅允许封面的 cardId、photoPath、photoBucket 都与当前摘要匹配时绑定图片。新推荐先清除旧绑定；过期下载结果丢弃。下载期间推荐已改变时，NearbyPage 在发起远端同步前再次检查当前推荐。
4. 通过 Form Kit `formImages` 的文件描述符和 `memory://` 图片名称传递，每次绑定使用新图片名称；更新完成后关闭描述符，创建回调的描述符保留到卡片移除或 FormExtensionAbility 停止。图片编码资源使用 finally 释放。
5. 参考官方[本地/网络图片刷新说明](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/form/arkts-ui-widget-image-update.md)，避免直接把应用 file:// 路径作为跨进程图片来源；该官方说明也要求刷新时更换 memory 图片名称。
6. 云端 `serviceCardFormData` 新增 photoPath、photoBucket。数据库 FoodCard 不直接保存图片路径，因此从 CardMedia 的公开主图元数据取得身份，沿用既有主图排序和审核筛选。查询失败时仍发送文字，图片身份置空。未改 Cloud DB schema、云对象方法签名或生成代理。

边界：远端推送传递图片身份，不直接传递图片字节。已缓存且身份匹配的图片可继续显示；应用关闭时收到一条没有对应本地绑定的新推荐，显示占位，下次应用前台发布这条推荐时补齐图片。刷新按钮不会从后台下载新图。

要验证远端图片身份匹配，需将本次 `CloudProgram/cloudfunctions/shike-service/runtime.js` 更新部署至目标测试后端。普通本地 UI/封面验证可先进行；已有后端的公开媒体功能需正常。部署说明见仓库 `CloudProgram/README.md` 第 4 节，部署包应包含修改后的 runtime.js。本轮未部署任何云资源。

## ArkTS 严格模式静态审查

以下为人工源码审查及本机 SDK 声明核对，不是编译器或运行测试结果。

| 检查 | 结果 |
| --- | --- |
| 新增对象字面量与 DTO | 路由参数、事件参数、ProxyData、Preferences Options、Image DecodingOptions/PackingOption 均有明确接口类型；formImages 为 Record<string, number> |
| Object / JSON 边界 | Want 参数先用 typeof 判断；JSON 事件使用明确 DTO 并核对非 null、object、message 的 string 类型；Preferences 数组逐项检查字符串 |
| any / unknown / 动态对象访问 | 新增逻辑未使用 any、unknown、动态对象结构或展开语法；图片键使用有明确值类型的 Record |
| catch / throw | catch 值不作未收窄访问；新增 throw 为 Error 实例 |
| 图片资源与 FD | 缩略图尺寸/大小受限；更新 FD 在 finally 关闭，创建 FD 在 remove/stop 关闭；PixelMap/ImageSource/ImagePacker 均释放 |
| Preferences 生命周期 | 写摘要及写封面分别在同步方法中完成，不跨 await 持有并使用被移出缓存的实例；读取时重载缓存以支持不同进程 |
| 布局与事件 | 固定双按钮行已移除；价格与短评分分别约束；刷新、正文和图片无嵌套点击；尺寸回调、图片错误事件、字体适配均与 SDK 的 @form 声明核对 |
| 配置与资源 | src、FormExtensionAbility、formName、两个 supportDimensions、默认规格和新增资源引用逐项核对；新增主题资源两套齐全 |

| 差异范围 | Application 与外层仓库的 git diff --check 均无空白错误；NearbyPage 和 runtime.js 原有改动保留，仅修改卡片相关位置 |

## 用户验证步骤

按顺序执行。第一步失败时先回传错误，不继续安装或设备操作。

1. **编译**：DevEco 打开 `Application`，同步工程并编译 entry。预期没有 ArkTS、资源或卡片配置错误。失败时反馈首条完整错误、文件/行号及前后约 20 行日志。
2. **添加与封面**：更新安装，检查原有 2×2；长按食刻图标进入服务卡片，分别添加 2×2、2×4。在应用中打开一条已有实拍图的公开推荐，待图加载后返回桌面。预期 2×2 展示摘要，2×4 展示同一推荐真实封面。反馈卡片选择器和桌面两规格截图。
3. **交互**：点顶部刷新，预期停留桌面，不拉起应用；点正文、再点 2×4 封面，预期都进入对应推荐详情。刷新可以不换内容，因为它重绘缓存。失败时反馈具体点击位置、实际跳转页和应用/设备日志。
4. **字体与主题**：分别切换默认/最大系统字体、浅色/深色，观察两种尺寸；有宿主调整尺寸入口时在两规格间切换。预期无底部裁切、价格被评分挤掉或图片遮字，长名称合理省略且详情可查看完整文本。反馈每种异常组合的桌面截图。
5. **图片一致性**：快速打开两条不同带图推荐，再返回桌面。预期最终名称与图片属于同一条推荐。随后使用无图推荐或在新图片尚未缓存时断网，预期显示“暂无封面”或“封面待加载”，保留文字，不继续显示上一条图片。反馈切换前后、占位状态截图。
6. **远端同步（部署后）**：沿现有同意与同步流程测试两种尺寸。已缓存的同一推荐应保留匹配的封面；不同推荐或不同主图收到远端身份变化时应隐藏旧图。应用关闭时的新图未缓存显示占位属于本轮约定行为；应用前台再次打开/发布该推荐后应补齐。反馈目标 formId（可局部遮盖）、投递状态/日志、前后台状态和两规格截图，不发送 Token 或凭据。

反馈同时附设备型号、HarmonyOS 版本、桌面网格设置、系统字体设置、DevEco 与 SDK 版本。
